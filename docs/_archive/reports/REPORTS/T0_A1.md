## TBD-47 — CLOSED. **H0 = 05:00.** And a correction.

I previously stated the grid could not disambiguate the slot convention and that only the
factory could answer. **That was wrong**, and wrong for the same reason revision 1 of the
fixture was inadequate: it rested on sampling two endpoint hours, which both readings satisfy.

Checked against the complete grid, 1,656 cells:

```
slot k = [k-1:00, k:00)  →  H0 = 05:00      0 mismatches / 1656
slot k = [k:00, k+1:00)  →  H0 = 06:00     69 mismatches / 1656
```

**The workbook uses slot 24.** The second reading would need an hour-of-day 24 to express it;
instead the instant rolls into the next date. It fails at exactly the 69 day-boundary cells that
land on slot 24.

`time.test.ts` keeps **both** readings and requires one to match every cell and the other to
fail, so the reasoning stays checkable rather than becoming a comment.

**Still open: TBD-50** — 05:00 in *which* timezone, and does it observe DST. `time.ts`
deliberately takes no zone; that lands on `TimeLabel` in C1.

Propagated to `TIME_CONTRACT.md §3.1`, `TIME_MODEL_CONFIRMED.md §2.2/§4/§5`,
`BUILD_SEQUENCE_KIRO.md`, `KIRO_BRIEF.md`.

### ⚠ Caveat — this was NOT verified against an empty project

The tables already existed in the deployed project, so `create table if not exists` would have

substitute and it is strong, but **a run against a genuinely empty Supabase project is still
owed** and remains A1's stated exit proof.

### Decisions taken, and why they are not inventions

- **`batch_status` = `draft, active, closed, cancelled`** — the deployed enum.
  `DOMAIN_MODEL §2.4` lists seven (adds `configuring`, `validated`, `in_tunnel`). The narrower
  set is what the code produces and what is deployed; adopting the wider one would add states
  nothing can reach, which is inventing workflow. Noted in the file.
- **`master_batch.code` UNIQUE** — deployed, so kept. **TBD-6** (on what cycle batch numbering
  resets) stays open and is marked at the constraint; removing the constraint would have been a
  behaviour change.
- **No FK on `batch_activity.tbd_marker` or `batch_activity_value.conflict_id`** — matching the
  deployed schema, even though the template tables `process_activity` and `activity_field` do
  carry them. Flagged rather than silently "fixed".
- **`or current_app_role() is null`** in the admin-write policies — deployed, and it is the
  escape hatch for a project where the Customize Access Token hook is not yet enabled. Kept,
  with a comment that it is dead code once the hook is on and should then be removed.
