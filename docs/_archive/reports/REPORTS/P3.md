## 1 · The correctness rule the whole page is shaped around

`v_batch_variance.variance_minutes` is the **worst stream**. `v_variance_contributor` ranks across
the **whole batch**. Join them naively and the paragraph reads:

> MB-118 is 3h 20m behind. Most of it — 2h 40m — came from the paddy soak.

where the paddy soak sits in a stream the headline did not come from. The sentence is arithmetic
nonsense *and* it names the wrong person to go and ask — worse than showing nothing.

So `loadBatchPage` filters contributors to `worst_stream` before ranking or capping. Within one
stream activities are sequential and their minutes genuinely accumulate; that is the only reading
under which the paragraph's arithmetic is true. The DB assertions recompute it independently: for
every batch with a measured variance, **top three plus remainder equals the headline exactly.**

Live proof, `MB-DEMO-LATE`: 44 + 44 + 44 + 99 = 231 minutes = `3h 51m behind`.

## 2 · Migration 0024 — so the paragraph can name a conflict

`v_variance_contributor` had every fact §11.2 needs except the marker itself. The paragraph could
name the person, the machine and the recorded cause, then fall silent on the one thing the reader
most needs: that nobody has decided which spec applies.

Rendering it without that would be worse than not rendering it — a GM reading a disputed value with
no marker concludes the system judged it acceptable. It did no such thing.

`tbd_marker` appended after `rank`, so column order is untouched and every existing caller works
unchanged.

## 3 · What the paragraph refuses to do

| Rule | How it is kept |
|---|---|
| Generated from the record, never authored | every clause is guarded by the fact it states; a missing fact removes the clause rather than softening it |
| Names people and machines | and **says so** where none is recorded — an unattributed delay is a finding |
| Quotes the reason verbatim | `<q>{c.cause}</q>`, never sliced, cased or summarised |
| Names the conflict | `ConflictMarker` at the point of use, with the note that the system did not judge |
| Null is not zero | "Nothing has been recorded against MB-X yet" — never "on plan" |
| No forecast stated as fact | prefixed *at this rate*, and omitted entirely without H0, scale, zone **and** a measured variance |
| No percentage | §8.3, and rule E.1 auto-fails the workstream for one |

## 5 · FOUR DEFECTS FOUND BY OPENING THE PAGE. THE SUITE CAUGHT NONE OF THEM.

This is now the third session in a row where the browser found what the tests did not. It is worth
stating plainly rather than burying in a changelog.

### 5.1 The rail said "nothing submitted yet" above twelve named submissions

`MB-DEMO-EARLY`'s ACTUAL rail read *nothing submitted yet*, directly above an event stream listing
twelve submissions by name, with times and reasons.

**Cause.** In `segmentsFor`, `from` was clamped up to 1 while `to` was computed from the **raw**
`baseline_start_hour`. Every Day-0 activity carries `baseline_start_hour = 0` — H0 is an *instant*
and the interval scale is 1-based (`TIME_CONTRACT §1.2`) — so the pair came out `from = 1, to = 1`.
`mergeSegments` drops zero-width segments, correctly, and eleven recorded activities vanished off
the axis. `actualPct` went null, and the rail said so.

**Fix.** `to` is derived from the clamped `from`. An activity with no stated end occupies exactly
one hour — a display convention, not a factory claim; TBD-21 records that several activities have
no duration stated, and one hour is the narrowest width that keeps the work visible.

A DB assertion now runs that arithmetic over every recorded row and **also** asserts the
hour-zero case is present, so the loop cannot pass on data that never exercises it.

### 5.2 Two correct numbers making a false sentence

> 3 deviations are waiting on a verdict. 3 stand on the record for this batch.

Any reader totals that to six. 0017 defines `awaiting_verdict` as `(open, escalated)` and
`stands_on_record` as `(open, escalated, accepted)` — the first is a **subset** of the second.

Both numbers were individually correct, which is exactly why no assertion caught it. Now stated as
one set, once: *"3 deviations stand on the record, all of them still waiting on a supervisor's
verdict."*

### 5.3 "the slowest of the four"

Four is a number this file does not know. `PROCESS-2026B` has four streams today; the stream list
comes from the process definition and a fifth would make the sentence false with nothing failing.
Same class as the baseline-hours literal rule 4 bans — in prose instead of code. Now "the slowest
one".

### 5.4 The event stream scrolled the whole page on a phone

`scrollIntoView({ block: 'nearest' })` walks every scrollable ancestor. At 390 px it scrolled the
page as well, landing the reader below the rail and the paragraph the moment a batch opened — and
§S2's phone rule is explicit that the narrative comes first there. The offset is set on the list
element directly now; nothing outside that box moves.

### Two more, off this page, found on the way

- **The nav still said "Command Center"** and pointed at `/gm/command-center`. That still resolves —
  it is kept as a redirect for the GM's bookmark — but routing every in-app click through a
  redirect, under the screen's previous name, is how a rename stays half-done forever.
- **The sign-in screen rendered the demo password uppercase.** `uppercase` was on the paragraph;
  the password is `mushroom2026` and is case-sensitive. Anyone typing what the screen showed was
  rejected — I was, twice, before reading the source.
