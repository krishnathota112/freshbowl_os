# Scope gap — the Freshbowl workflow document against what is built

**23 August 2026.** Source: `Freshbowl Mushroom Composting Workflow Automation.docx`, read today.

## The short answer

**No — Excel export is not the only thing missing.** The document describes ten modules across five
phases. **One of them is largely built** (§6, the composting workflow), two are partly built, and
**four do not exist in any form** — not a screen, not a table, not a column.

The document is a full production ERP: planning → formulation → material testing → weighment →
composting → tunnel → growing rooms → harvest → yield and cost. What has been built is the middle
of that chain, built deeply. The two ends — what happens before material arrives, and what happens
after compost leaves the tunnel — are absent.

That is not a criticism of the build. §6 is the hardest module in the document and it is the one
that carries the 552-hour clock, the gates, the deviations and the audit trail. But "did you do all
the things" has to be answered honestly before a demo, not after.

## Section by section

### §1 · Monthly planning of batches — **NOT BUILT**

| | |
|---|---|
| Exists | `master_batch` (code, label, Day 0 date, H0 instant, status, supervisor). `location_occupancy` and `v_machine_utilisation` already model bunker and tunnel occupancy. |
| Missing | The monthly plan itself. Month/year, rooms planned per batch, planned bunker/tunnel/room numbers, planned dates for each of the eight stages, estimated tunnel-out and harvest dates. |
| Missing | Bunker / tunnel / growing-room **utilisation plans**, the **double-allocation conflict warning**, and the **delayed-batch alert**. |
| Note | `/admin/schedule` is declared in the plan and **ships blocked** on C-19 and C-20 — the day-numbering base moved and the conflict is unresolved. |

**A status the document wants that we do not have:** it lists *Planned / In progress / Delayed /
Completed / Cancelled*. The system has `draft / active / closed / cancelled` — **there is no
`Delayed` status.** Delay is derived from recorded variance instead of being a state somebody sets.
That is a real design difference and it is not being reconciled silently: whether "delayed" is a
fact the system computes or a flag a planner raises is the factory's call.

### §2 · Raw-material formulation — **NOT BUILT**

| Missing | Formulation versions and the retained original, C:N estimate, total dry matter, percentage contribution per material, estimated batch cost, quantity per room, quantity per bunker. |

`cn_ratio` exists — but as a **reading recorded on an activity**, not as a formulation calculation.

### §3 · Raw-material testing — **PARTLY BUILT, and not the same thing**

| | |
|---|---|
| Exists | A complete laboratory module: samples, tests, immutable versioned results, retest chains that never overwrite, specs, methods, instruments, calibration status, verdicts, decisions. Migration `0022`. |
| **But** | It hangs off **in-process checkpoints**, not off raw-material lots. It answers "what is the moisture in bunker 7 on day 5", not "is this truck of paddy straw fit to use". |
| Missing | `supplier` and `material_lot` do not exist as tables. Without a lot there is nothing to approve. |

### §6 · Composting activity workflow — **LARGELY BUILT**

The core, and it is real.

| | |
|---|---|
| Exists | The process as **data** — `process_definition`, `process_day`, `process_activity`, `activity_variant`, `activity_field`. Adding an activity, a duration or an evidence requirement is a seed change with no application code. |
| Exists | 552-hour batch clock, planned vs actual start and completion, duration, variance in minutes, responsible employee, supervisor, machine, bunker/tunnel assignment, quantity handled. |
| Exists | Readings: `moisture_pct`, `temp_c`, `ph`, `ec`, `n_pct`, `ash_pct`, `cn_ratio`, `water_qty_l`, `fill_height_m`, `pasteurisation_temp_c`, and 19 more. Phase-II control bands are seeded. |

### §7 · Growing-room filling — **NOT BUILT**

Nothing. `location` holds `TUNNEL`, `BUNKER`, `SOAK_PIT`, `HOPPER`, `YARD` — **there is no
`GROWING_ROOM` kind at all.** No fill record, no spawn batch, no bed area, no compost weight per
square metre.

Every traceability question the section asks — *which batch entered which room, which rooms came
from which batch, which raw-material lots* — is unanswerable, because the chain stops at the tunnel.

### §8 · Mushroom harvest — **NOT BUILT**

Nothing. No table, no column, no screen. Harvest date, flush number, grade, quantities, pickers,
yield percentage, kg per square metre, yield per tonne of compost, break-wise yield, picker
productivity, grade recovery, batch profitability — none of it exists.

## Three conflicts to put to the factory — not resolved here

**1 · Offline capture.** The document requires *"offline capture where network connectivity is weak,
automatic synchronisation when connectivity returns."* The system is built the opposite way, on
purpose: `C-FIELD` chose one online application after the client confirmed reliable realtime
internet and roughly thirty users, and a test actively fails the build if a service worker appears
anywhere in `src/`. **Both positions are on record and they contradict each other.** Offline capture
means a client-side write queue and conflict resolution, and it is at odds with server-authoritative
gates — the guarantee that a device clock can never open a rest window. Somebody has to choose.

**2 · `Delayed` as a status.** §1 wants it as a batch state. The system derives lateness from
recorded variance instead. A status somebody sets and a number the system computes can disagree, and
the document does not say which wins.

**3 · Live-photograph enforcement.** The document wants gallery photographs blocked unless
authorised. Enforcing that on Android needs the camera intent rather than a file picker, and it
changes what an operator can do when a phone's camera fails. It is a policy decision with an
operational cost, not a toggle.

## Is everything connected?

**Yes, for what exists.** Verified end to end today in the browser against the live database:

```
create batch → generate plan → activate → operator starts → records readings
   → uploads evidence → submits → out-of-range raises a deviation
   → supervisor sees it in Control Room → accepts / returns / escalates
   → gate opens on the SERVER clock → rest runs → next activity opens
   → every step lands in the event stream and the narrative
```

Every write goes through a database function — `create_master_batch`, `generate_activity_plan`,
`activate_batch`, `start_activity`, `bind_evidence`, `submit_activity`, `release_activity`,
`hold_activity`, `return_activity`, `accept_with_deviation`, `escalate_deviation`,
`open_lab_sample`, `request_lab_test`, `record_lab_result`, `order_retest`,
`release_elapsed_rests`. Nothing writes a table directly from the browser.

Row-level security is enabled on all 45 tables. The role is a signed claim in the access token, so
editing browser storage changes nothing.

**Confirmed live today:** the deviation Ravi raised as operator appears in Ramarao's Control Room
with the reason recorded verbatim; the lab reading recorded as K. Menon appears on the batch record
with its checkpoint, its map and its calibration status; the GM's narrative names K. Menon as the
largest contributor to MB-DEMO-LATE being 3h 51m behind.

**What is not connected is what does not exist.** There is no link from tunnel to growing room,
because there is no growing room. There is no link from compost to yield, because there is no
harvest.
