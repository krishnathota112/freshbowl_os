## Criterion 62 is enforced by the compiler, not by review

A band with no backend must never show a zero — a zero reads as *"nothing is wrong"*, which is a
lie a supervisor would act on. So the contract is a union:

```ts
export type Band<T> =
  | { built: true; rows: T[] }
  | { built: false; releasedWith: string; why: string };
```

Only the built branch has `rows`. Verified by probe:

```
error TS2339: Property 'rows' does not exist on type 'Band<{ x: number; }>'.
  Property 'rows' does not exist on type '{ built: false; releasedWith: string; why: string; }'.
```

Same reasoning as `Bar`'s required `kind` for A4 — a type error beats a checklist item.

## The room disagrees with the server nowhere

- **Awaiting-release is computed the way `release_activity` checks it.** The server refuses while
  anything still awaits a verdict; listing an activity the server would refuse is the frontend
  contradicting the authority.
- **A protected gate offers escalation, not an accept it would be refused** (§3.2).
- **The reason rule is not re-implemented.** The server refuses an empty reason and its message is
  what the user sees. The button is disabled while the box is empty as a courtesy, not as the rule
  — two places deciding what counts as a reason is how they drift apart.
- **The countdown never claims a gate opened.** It renders "window open — opening now", and the
  next poll asks the server.
